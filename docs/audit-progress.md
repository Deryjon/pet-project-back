# Журнал исправлений по аудиту

Источник задач: `docs/audit-report.md`, копия `pets/docs/audit-report.md`.

Ветки `audit-fixes`:
- бэкенд — от `main`;
- фронт — от `dev`, потому что там идёт основная разработка, а `main` фронта отстаёт.

В `main` ничего не коммитится и не мержится.

Журнал лежит в репозитории бэкенда: `pets/docs` не входит в git. После коммита пункта во фронте журнал обновляется отдельным коммитом здесь.

Проверки перед каждым коммитом:
- **Бэкенд:**
  - `npm run build:typecheck`;
  - `npx jest` (все тесты);
  - eslint по изменённым файлам: число ошибок не должно вырасти относительно базы ветки. `npm run lint` не используется, потому что он запускает `--fix` по всему репозиторию, а там уже около 800 ошибок, в основном prettier.
- **Фронт:**
  - `npm test`;
  - `npx nuxt typecheck` вместо lint, отдельного lint-скрипта нет;
  - `nuxt build`.

### 5. Отмена возврата и обмена (топ-10 №4, 🔴5)
- **Коммит:** `fix(sales): free returnable quantity and debt credit when a return is cancelled`.
- **Что изменено:**
  - `getReturnableQuantities` не учитывает отменённые возвраты. После отмены ошибочного возврата товар можно вернуть снова.
  - Новая колонка `Sale.debtCredit`, миграция `20261008090000_sale_debt_credit`: добавлена колонка со значением по умолчанию 0, существующие данные не меняются. В неё сохраняется сумма, которую возврат или обмен зачёл в долг исходной продажи.
  - При отмене возврата эта сумма возвращается в долг, и `Client.debtUzs` пересчитывается.
  - У возвратов, сделанных до этой версии, `debtCredit = 0`: их зачёт при отмене не откатывается.
  - Отмена возврата или обмена теперь выполняется в `runSerializableTransaction` и сначала захватывает статус всех документов группы. Второй параллельный запрос получает «Документ уже отменён».
  - `test:postgres`: «Migrated schema matches schema.prisma».
- **Как проверить руками:**
  - Продажа в долг, возврат части: долг уменьшился.
  - Отмена возврата: долг вернулся к прежней сумме, и товар снова можно вернуть.
- **Миграция:** применять к проду через `prisma migrate deploy` при выкладке. Я её применял только к временной тестовой базе.

### 7. Глобальный rate limit и security-заголовки (топ-10 №5, 🟠)
- **Коммит:** `fix(security): rate-limit every route and send security headers`.

- **Как проверить руками:**
  - Обычная работа не меняется.
  - 6-я попытка входа за минуту даёт 429.
  - В ответах API есть заголовки `X-Content-Type-Options` и `Strict-Transport-Security`.
- **Важно:** лимит пока 100 запросов в минуту на IP. Решение D2 ниже меняет учёт и значение.

## 🧭 Решения

### D1. Долг при отмене продажи
- **Коммит:** `decision(sales): annul an unpaid sale debt on cancel, block it once repaid` (хеш в `git log --grep "annul an unpaid"`).
- **Что выбрано:** при отмене продажи её долг (`ClientDebt.saleId`) удаляется, а `Client.debtUzs` пересчитывается, всё в той же транзакции. Если по долгу уже были оплаты (`repaidAmountUzs > 0`), отмена запрещена: «По долгу этой продажи уже есть оплаты: сначала верните их клиенту».
- **Почему:** в `ClientDebtStatus` нет статуса «отменён», а оставлять долг за отменённую продажу нельзя. Удалять частично оплаченный долг тоже нельзя: деньги клиента «пропадут» из учёта.
- **Альтернативы:**
  1. Добавить статус `cancelled` в enum (нужна миграция) и сохранять историю долга.
  2. Обнулять остаток, а не удалять долг.
  3. При частичной оплате переводить оплаченное в баланс клиента.
- **Как откатить:** `git revert <хеш коммита D1>`; останется только атомарная отмена из пункта 4.

### D2. Учёт rate limit по токену, 600 запросов в минуту
- **Коммит:** `decision(security): rate-limit per user token, 600 requests a minute`.
- **Что выбрано:**
  - `AppThrottlerGuard` считает запросы по хешу заголовка `Authorization`, то есть по пользователю. Запросы без токена (вход, вебхуки) считаются по IP.
  - Значение по умолчанию 600 в минуту. Его можно поменять через env `THROTTLE_LIMIT_PER_MINUTE`, без изменения кода; переменная добавлена в `.env.example`.
- **Почему:** кассиры одного магазина обычно выходят в интернет с одного IP. При лимите 100 в минуту на IP касса с поиском по каждой букве упрётся в лимит. 600 в минуту на пользователя — это 10 запросов в секунду: запас для POS, но защита от перебора и скриптов остаётся.
- **Альтернативы:** лимит по IP с большим значением; Redis-хранилище для нескольких инстансов (сейчас один PM2-процесс, достаточно памяти).
- **Как откатить:** `git revert <хеш D2>`, тогда вернётся 100 в минуту по IP.
